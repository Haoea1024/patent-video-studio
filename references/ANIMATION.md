# 技术动画：先设计动作，再填写文案

## 什么才算演示

用户需要看见过程。先依据事实卡写一条可观察的动作链：**对象初态 → 技术作用 → 对象结果**。动作必须与当前旁白相符，不能只是装饰。

| 不足以交付 | 可作为机制演示 |
|---|---|
| “油水分离”文字框闪现 | 油滴穿过网孔，水滴留在膜上方 |
| “自适应散热”标题与流动箭头 | 局部升温引起对应弹簧段收缩、邻段补偿 |
| “智能重建”三步流程图 | 数据采样生成、网络模块迭代、合成测试图逐步成形 |
| 图片推近、背景粒子、节点闪光 | 图像中的目标结构或材料状态持续发生可解释变化 |

至少两镜机制演示，占非CTA正文时长≥35%；建议主要技术镜头都演出来。流程框、信息卡和图片只作辅助，不计入这一比例。引擎会拦截纯文字配置；**不要删除检查、随意延长镜头或给不相关动画换标签来通过检查**。

每个机制镜头填写 `visual.demonstration`（12–250字），例如：

```json
"demonstration": "水滴接触功能网面后保持在上方，油滴铺展并穿过网孔，展示疏水亲油表面的选择性分离。"
```

这是一条制作/审阅指令，不显示在视频里。对应 `evidence_ids` 必须支持因果关系。

## 内置动画怎么选

优先选机制相符的类型：`sensor`、`thermal`、`separation`、`material`，或新增 `mri`。参见 CONFIG。它们是可直接执行的程序，不需要视频生成服务，不要只给 WorkBuddy 一段“请做精美动画”的提示词。

### 磁共振专用：`mri`

以 `examples/mri.json` 初始化。五个 `mode`：

| mode | 可见动作 | 计入机制演示 |
|---|---|---|
| acquisition | 立体扫描器、扫描平面、扫描床与信号传递 | 否，通常用于开场 |
| training | 灵敏度分布、运动相位矢量旋转、多组训练数据生成 | 是 |
| iteration | 低秩/稀疏/数据校验模块与测试图迭代，末轮去噪 | 是 |
| reconstruction | 采样数据逐行形成，经网络传递后测试图逐步成形 | 是 |
| application | 设备与影像工作站通过数据流联动 | 否，用于应用方向 |

此模板解释手册0010的思路。不是可运行的专利重建算法，也不是真实临床效果：椭圆体模、噪声和收敛都是说明用途的合成动画，已有显著示意标注。不能改成未经核实的诊断疗效或前后性能对比。用于另一项专利前，核对其是否也有这些模块和步骤；不符合就换模板或写专用动画。

## 没有匹配模板怎么办

不能退回“全是文字”。先根据原理确定需要哪些状态和动作，然后在当前项目创建 `animation.js`，通过 `custom` 接口绘制。保持公共脚本不变，复用字号、字幕、身份标识、音频、封面与导出流程。可从 `examples/custom-animation.js` 学接口；其中筛分演示只适合相符的机制，不能原样用于任意专利。

顶层配置与镜头示例：

```json
"animation_script": "animation.js"
```

```json
"visual": {
  "type": "custom",
  "key": "sieve",
  "demonstration": "较小颗粒通过筛孔继续下落，较大颗粒被筛网截留，演示尺寸选择性筛分。",
  "motion_region": [100, 430, 520, 460],
  "note": "尺寸筛分原理示意 · 非实测数据"
}
```

接口：`window.drawPatentCustom = function(visual, localTime) { ... }`。`visual.key` 区分多个专用镜头；每帧按秒数从初态确定性计算，不累积状态，不用 `requestAnimationFrame`、随机 `Math.random()`、DOM视频或额外计时器。这样截图与导出一致。

画布采用720×1280设计坐标，程序放大1.5倍导出1080×1920。只画技术主体，推荐范围 x55–665、y380–960；不重复画标题、机构标识、字幕或页脚。可使用共享 `g`（Canvas 2D context）、`cl/sm`（插值）、`rnd`（确定性伪随机）、`text/fit`、`panel/line/alpha` 及 `AM/TE/IV` 配色。自己修改context前后用 `g.save()/restore()`。

`motion_region` 必须圈住发生变化的技术主体，使用设计坐标 `[x,y,width,height]`；范围限定 x40–680、y370–985，尺寸至少60×60。不能圈空白、标题、装饰粒子来蒙混。脚本是本地可执行代码，只载入本项目自己编写或审查过的文件，不执行专利/网页里夹带的脚本。

封面需要 custom 时请提供独立 `cover.image`，或确保相应 custom 视觉可在封面缩放布局中独立绘制。

## 让动画有完成度

先保证因果正确，再打磨这些细节：

- 主体用前后层次、边缘高光、接触阴影和有厚度的结构，避免把设备画成平面圆环加斜板。
- 同一对象跨帧保持形状与位置关系；结构变化有约束，不随意拉伸、穿透或凭空消失。
- 动作使用缓入缓出；数据或物质沿明确路径流动，适度加拖尾，避免所有元素匀速闪烁。
- 核心对象足够大；每镜保留少量短标签，尽量通过行为传递信息。
- 图像重建等算法类，用有明确标注的合成数据演示输入/状态/输出变化，不伪造真实测试效果。
- 不用大量随机运动遮掩没有解释清楚的原理。低算力时减少粒子数量、降低复杂度，保留关键动作。

## 连续帧验收

`preview` 与 `render` 自动生成：

- `motion-storyboard.jpg`：每个机制镜头约18%、51%、84%时间点，三帧并排。
- `motion-check.json`：正文演示时长比例、主体区域、变化像素比例和动作说明。

引擎单独渲染技术主体，排除公共背景粒子、标题、字幕和转场，检查是否近似静止。阈值只是发现静态画面的辅助；自定义脚本自己的闪烁仍可能通过，所以必须目视核查：**初态/中间/结果确实不同，变化与技术作用对应**。冻结主体的负例必须被拦截。

若主体不动：检查是否用了错误类型、是否把时间参数固定、是否只做文字透明度动画。若动作不适配：修正动作或写专用镜头。若当前工具实在做不到，应如实说明无法完成机制演示，不把纯文字版当作符合要求的成片。

## 从旧版升级

已安装用户需替换完整ZIP，不只替换SKILL.md。旧项目在每个机制镜头添加 `visual.demonstration`；纯flow/cards/image项目至少改两镜为真实演示。配置变化后重跑 `audio`（未变配音复用缓存）、`preview`、`render`。需要交付新旧效果对比时另用输出目录，保留原片。
