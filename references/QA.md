# 成片验收与故障修复

## 自动检查已覆盖什么

- JSON 字段、长度、类型、未知字段、重复镜头 ID、出处引用存在性。
- 已知专利号与“专利号/申请号”等提示词不得出现在 narration。
- TTS 文本与词时间戳逐字对应；时序有效且不超过音频；旧项目哈希与新配置一致。
- 字幕最多两行，标题和卡片最低字号仍不越界；JavaScript 无报错。
- FFmpeg 可完整解码，帧数符合时长×24，存在附加封面。
- 至少两镜技术过程演示，非CTA正文演示时长≥35%；机制主体单独渲染后三时点像素变化，拦截近似静止的主体。
- 成片响度约 -21 至 -13 LUFS，真峰值不高于 -1 dBFS；有配乐时，人声有效区间的中位电平差至少 14 dB（常见约 21 dB）。

这些检查不证明事实准确、配音读音正确或镜头语义合理。不能把 passed:true 当成省略内容复核的理由。

## 人工/模型目视检查

| 对象 | 看什么 | 不通过怎么改 |
|---|---|---|
| source 页 | 项目边界、标题号码、成熟度、机制方向 | 查原始专利，不从邻项借结论 |
| storyboard.jpg | 六镜节奏、主体位置、文字密度 | 缩短 headline/items；换适用镜头 |
| motion-storyboard.jpg / motion-check.json | 对象在初态/中间/结果的可见变化及技术因果；装饰闪烁不算 | 逐条核对demonstration，修动作或改用custom；不降低阈值绕过检查 |
| 单帧 PNG | 中文没有缺字、字幕不挡主体、图例可读 | 修字体和文案，不无限缩字体 |
| cover.png | 大标题吸睛且真实、无错字/方向错误 | 改提示词或用排版封面 |
| final-first.png | 第一帧机构标识与正文可见，没插封面 | 检查 renderer 与导出映射 |
| final-last.png | 联系方式、成熟度、结尾字幕统一 | 修配置，不混用旧项目截图 |

至少检查开头、原理关键帧、成熟度、结尾。动态语义还要播放或查看相邻时刻帧：箭头方向、粒子位置、弹簧形变和液相透过不能只凭静态首帧判断。

## 试听检查

听前 10 秒、技术原理段、最后 10 秒：专业术语/多音字、数字、停顿、语速、爆音和音乐遮盖。模型没有音频理解能力时，不写“已试听无误”，只报告自动响度检查和待用户试听的读音项。语音出错可在 narration 中用自然同义表达改写，避免错误扩写缩写；修改后重新 audio。

## 不能出现的历史问题

- 再选老师或用户已做过的同一个项目，却声称是新选题。
- 在视频底部额外加音乐署名条，挤占原有布局。
- 把封面展示为片头，或把专利号念一遍。
- 结尾突然换一套字幕样式。
- 为了“更厉害”把实验阶段写成成熟量产。
- 新专利仍带上个项目的号码、机构、配音、图片或联系方式。
- 把一张静态图拉长 60 秒，声称与三个动态图解样片等效。
- 把流程框、卡片入场和背景粒子当成技术演示；遇到新领域就自动退回纯文字。
- 无 API/工具时假造文件链接或把 HTML 冒充 MP4。

## 复核记录

`validation.json` 是自动报告；人工核查可在项目目录写 `review-notes.txt`，注明检查了哪些源页、关键帧和实际试听情况。不得把未做的人工检查写成已通过。

若要比较国产模型效果，给不同模型同一 PDF、同一 skill 包、同样的外部工具权限，并记录实际模型名、语音/绘图服务和是否使用排版封面。这样能区分内容理解差异与工具可用性差异，不把所有变化都归因于模型强弱。
